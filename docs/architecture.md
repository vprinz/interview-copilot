### Предложение: В, запасной путь — Д

Почему В:
- **Закрывает П1 по построению.** Нет модели, которая может «ответить что-то», и нет пределов CLI. Неполноту API называет сам, а не прячет.
- **Формат не меняется.** Синтаксис тот же, что видно в текущих `context.md`, поэтому разбор (шаг 2) один для Notion и для файла.
- **Быстрее и бесплатно:** 1–2 с вместо ~15 с и ни одного запроса из лимита подписки.

Проверки, после любой из которых запуск **останавливается** с понятным сообщением, а сессия не стартует:
1. HTTP не 200 → код и текст ошибки Notion (401 — нет токена, 404 — страница не подключена к интеграции, и так далее).
2. `truncated: true` → дочитать каждый id из `unknown_block_ids`. Если после этого что-то осталось недоступным — стоп со списком блоков.
3. В markdown остались теги `<unknown …>` → стоп со списком. Если это закладки или встраивания, которые в гайде не важны, — флаг `--allow-unknown`.
4. Заголовок страницы из `GET /v1/pages/{id}` записывается в `guide.notion.json` и печатается при запуске: видно, что скачан именно нужный гайд.
5. Содержательная проверка — в шаге 2: если разбор не нашёл ни одного блока, это стоп.

Токен: `security find-generic-password -s interview-copilot-notion -w`, запасной вариант — переменная `NOTION_TOKEN`. Положить токен в Keychain нужно тебе самому, команду дам в фазе 2. Права интеграции — только чтение содержимого. Что уходит наружу, не меняется: читаем страницу, которая уже лежит в Notion.

*Проверено в фазе 2 (2026-10-15):* на шаблоне гайда markdown из API совпал с ответом MCP построчно (728 строк), разбор — тоже. Гайд на два созвона (84 КБ, тот, что не загрузился 13.10) пришёл одним запросом за ~1 с, без `truncated`.

### Что сохраняется из оформления

`guide.notion.md` хранит страницу без единой правки. Что разбор делает с оформлением:

| В Notion | Что значит в гайде | В `guide.json` |
|---|---|---|
| `<columns>`: левая колонка | сценарий блока: что спрашиваю | поля блока |
| `<columns>`: правая колонка, `## <span color="green">…</span>` | что записываю; после части 1 там ответы респондента (📝) | `record`: заголовок, поля и записи. Модели нужны для части 2 |
| `<span color="gray">` | пояснения, иллюстрации, «изменено после пилота» | `hints` с пометкой «пояснение». Не путать с вопросами |
| `<callout>` до первого блока | карточка, подстановки, «если не успеваешь», ловушки, маршрут | раздел гайда по иконке: ✂️ → `cut_order` и `never_cut`, ⚠️ → `traps`, 🗺️ и таблица «к какой минуте» → `timeline`. Остальные — в `notes` |
| `<details>` / тоггл-заголовок | свёрнутый справочный материал | содержимое сохраняется, `collapsed: true` |
| `<table>` | таблица времени, стоп-лист, таблицы для записи | разбирается по шапке («К какой минуте», «Антипаттерн»), остальные таблицы — как текст |
| `<mention-date>`, ссылки | даты созвонов, ссылки на блог | текст как есть |

**Ни одна строка не теряется молча.** У разбора есть проверка: каждая непустая строка исходника попадает в какое-то поле `guide.json`. Строки, которые не подошли ни под одно правило, уходят в `unparsed` своего блока и перечисляются в `guide.report.txt`. Тест проверяет это на всех образцах.

## 3. Шаг 2 — блоки гайда (`guide.json`)

### Правила разбора

Правила записаны по шаблону гайда в Notion и по настоящему гайду на два созвона (13.10):
- `# Часть N — …`, `# Между созвонами …`, `# После интервью …` → **часть** звонка (`call`, `break`, `after`). Если частей нет, весь гайд — одна часть.
- `# N. Название — время` → **раздел** (например «3. Детально изучаем задачу — ~15 мин»), блоки внутри него — его дети.
- `## N.M [название] пометки — время` или `## N. Название — время` → **блок**. Номер из гайда и есть его id: `3.5`, `0`, `6а`. Блок без номера («Вход — 2 мин», «Закрытие») получает id из части и названия (`ч2-вход`). Разбор пишет об этом в отчёте.
- *Уточнено в фазе 2:* в гайде на два созвона номера повторяются в разных частях («5. Переход» в части 1 и «5. Хвост перехода» в части 2). Такие блоки получают id с частью: `ч1-5`, `ч2-5`. Повтор номера внутри одной части — ошибка.
- *Уточнено в фазе 2:* блоки до первой «# Часть …» (как в шаблоне, где частей нет) — неявная часть `ч1` «Звонок».
- Правая колонка: зелёные заголовки группы `<columns>` раздаются блокам левой колонки при её закрытии — по общим словам в названии («Негативные эмоции ДО» → 3.8, даже если справа порядок другой), при равном числе — по порядку, иначе первому блоку.
- Время: `— 5 мин`, `— 3–5 мин`, `— ~15 мин`, «5 мин вместе с 3.6» → `minutes: {min, max}` и `shared_with`.
- Пометки в заголовке: ⭐ → `star`, ✂️ → `cut` (режется первым), ⚠️ с текстом («не резать», «не пропускать», «обязательно», «не репетиция») → `must` и текст, 🔧 → `marks` как есть.
- Внутри блока: `> 📖 «…»` → вопрос (`verbatim`), `*Иначе:*` → запасная формулировка к предыдущему вопросу, ✅ → добивки, ⚠️ и ❌ → ловушки, серый текст → пояснения.
- Таблица «К какой минуте … Что должно быть закрыто» → `deadline_minute` у блоков, номер которых стоит в начале ячейки.
- `## Стоп-лист …` с таблицей → `stop_list`.

### Схема (сокращённо)

```json
{
  "schema": 1,
  "source": {"kind": "notion", "page_id": "…", "title": "…", "edited": "…", "sha256": "…"},
  "title": "2026-10-13 — …",
  "parts": [
    {"id": "ч1", "kind": "call", "title": "Часть 1 — 30 минут", "minutes": 30,
     "blocks": ["0", "1", "2", "3.1", "3.6", "5", "6", "10"]}
  ],
  "blocks": {
    "3.5": {
      "id": "3.5", "part": "ч2", "section": "3", "title": "триггер",
      "minutes": {"min": 3, "max": 3}, "deadline_minute": null,
      "star": false, "cut": false, "must": null,
      "items": [
        {"kind": "question", "text": "В какой момент ты обычно начинаешь…", "line": 412, "label": ""},
        {"kind": "alt", "text": "После какого события…", "line": 413},
        {"kind": "check", "text": "Триггер — событие, а не состояние…", "line": 414},
        {"kind": "trap", "text": "Разведи два момента…", "line": 416}
      ],
      "records": [{"title": "Триггер", "line": 420, "items": [{"kind": "field", "text": "- Событие:", "line": 421}]}],
      "collapsed": false
    }
  },
  "cut_order": ["8", "7", "3.2", "3.9", "3.10", "3.7", "3.8"],
  "never_cut": ["3.1", "3.3", "4.2", "4.3", "5.5", "6", "9", "10"],
  "traps": ["Съезд в производство контента…"],
  "stop_list": [{"pattern": "Вопрос про будущее…", "why": "Человек не знает…"}],
  "notes": ["…остальные callout'ы по порядку…"],
  "warnings": ["блок «Вход» без номера → id ч2-вход"]
}
```

*Уточнено в фазе 2:* содержимое блока — один упорядоченный список `items` с видом строки (question, alt, check, trap, hint, text, quote, heading, table), а не отдельные списки: порядок нужен, чтобы показать блок модели так, как он написан. У каждой строки — номер строки в исходнике, чтобы найти её глазами.

`cut_order` и `never_cut` разбор достаёт из текста callout'а ✂️ («режь с конца: соседние задачи → путь к найму → …»). Что не сопоставилось с id блока, остаётся текстом и попадает в `warnings`.

**Проверки после разбора:** ни одного блока — стоп. Повторяющийся id — стоп. Блок без времени, сумма минут не сходится с `--minutes`, строки в `unparsed` — предупреждения в `guide.report.txt`. При запуске печатается короткая сводка: части, блоки, минуты, ⭐ и ✂️.

**Без гайда** (`--no-defaults --context …`, как в прогоне по записи Андрея) берётся встроенный гайд по канону — *уточнено в фазе 2:* `canon-guide.md`, который разбирается тем же парсером, а не готовый JSON: шесть блоков канона на 60 минут (контакт 3–5, квалификация до 10, …). У панели и сессии всегда один и тот же вход — `guide.json`, отдельной ветки кода «без гайда» нет.

## 4. Шаг 3 — сессия nmt-chat

Требования CLAUDE.md не меняются: скилл `nmt-chat`, канон, одна долгая сессия на интервью, контекст из `~/projects/curator-product` (product.md, research/design.md). Меняется только то, как в сессию попадает гайд.

- `context.md` = product.md + design.md + **гайд, собранный из `guide.json`**. У каждого блока заголовок с id: `## [3.5] триггер · 3 мин · ✂️`. Под ним вопросы, ловушки, пояснения и записи правой колонки, каждый вид с подписью. Модель видит ровно то, что разобрано. Проверка «ни одна строка не теряется» гарантирует, что разобрано всё.
- `kickoff.md` собирается из шаблона `prompts/kickoff.md` с подстановками: `{context}`, `{minutes}`, `{part}`, `{blocks}` (компактный список: `id · название · минуты · ⭐/✂️/не резать`) и `{format}` — описание формата ответа, которое генерируется из контракта (раздел 5). Описание формата в шаблоне руками больше не пишется.
- Правило в kickoff: «В БЛОК и ВОПРОС пиши только id из списка блоков». Фокус исследования, «ПРОПУЩЕН: …» и правило «иди за интервьюером» переносятся из восстановленной версии без изменений.
- Запуск процесса не меняется: `claude -p --input-format stream-json … --tools Read --effort low --model claude-sonnet-5-5`, `NMT_NO_UPDATE_CHECK=1`, первое сообщение начинается с `/nmt-chat`.

## 5. Контракт ответа модели

Это одно место, где описан формат ответа: модуль `contract.py`. Из него берутся:
1. **Описание формата для модели** — текст `{format}` в kickoff, с примером.
2. **Парсер** строк потока: `parse_line(line) → Update | FormatError`.
3. **Состояние панели** `PanelState` — dataclass. Из него генерируется `panel-state.schema.json`, его читает страница. *Уточнено в фазе 3:* схема появится в фазе 5 вместе с новой страницей; в фазе 3 страница читает те же поля, что и раньше.

Сам формат остаётся строчным с «=», а не JSON. Причины: строки можно показывать по мере прихода (вопрос появляется раньше конца ответа), а «=» держит рост контекста около 330 токенов на обновление. JSON примерно в полтора раза длиннее, и за час звонка контекст упёрся бы в окно сессии.

```
СОБРАНО: результат ✓ клиенты из блога | критерии ≈ | контекст ✗ | триггер ✗ | выше ✓ … | эмоции ✗ | частота ✗ | важность ✗
ВОПРОС: 3.5 · триггер | В какой момент ты обычно начинаешь…?
ФЛАЖКИ: критерий абстрактный — до цифры | —
КАНОН: guide §7 банк вопросов
```

Правила разбора:
- Неизвестный id блока **не стирает** строку: она показывается как текст, в журнал пишется ошибка, на панели — жёлтая метка «формат: …».
- Строка не разобралась → прошлое значение поля остаётся, в `panel.jsonl` пишется `errors`, статус панели «ответ не по формату», а не пустота.
- Ответ без единой разобранной строки → статус «ошибка» с началом ответа: так случается при исчерпанном лимите и сбоях CLI.
- «=» — поле не изменилось. `ВОПРОС` всегда приходит полностью.

Тесты:
- образцовые ответы, синтетические, по одному на каждое правило и каждую ошибку;
- пример из `{format}` разбирается без ошибок: описание для модели и парсер не могут разойтись;
- **локальная регрессия по старым журналам:** скрипт `bench/reparse-journals.py` прогоняет все ответы из `recordings/live/*panel.jsonl` через новый парсер (для v1) и сравнивает состояние со старым разбором. Данные не покидают `recordings/`, в тесты не попадают.

## 6. Модель данных панели — что панель может показывать

Это вход для дизайна в Claude Design. У каждого поля указан источник.

| Группа | Поле | Источник |
|---|---|---|
| Шапка | часть звонка (1 из 2), её название | `guide.json` + `--part` |
| | таймер ММ:СС и минуты части; клик — сброс отсчёта | часы копайлота |
| | статус: готовлюсь / слушаю / думаю / ответ не по формату / ошибка; «обновлено N с назад», «следующее через N с» | копайлот |
| | «поверх окон» вкл/выкл | окно |
| Таймлайн | блоки части: id, название, плановые минуты или «к минуте N», ⭐ / ✂️ / не резать | `guide.json` |
| | у блока состояние: пройден / текущий / впереди / «резать» | модель (`БЛОК`) |
| | где мы по плану и где по факту → «отстаёшь на N мин» | часы + `guide.json` + модель |
| Текущий блок | id и название; что из обязательного впереди; что предлагается резать | модель + `guide.json` |
| | вопросы 📖 и ловушки ⚠️ этого блока из гайда (для широкого окна) | `guide.json` |
| Вопрос | текст словами респондента | модель |
| | к какому блоку относится (id → название из гайда) и что добирает | модель + `guide.json` |
| | состояние: новый / повторён / пропущен; кнопка «Пропустить» (S) | копайлот |
| Задачи | до 4 задач его словами; какую копать и почему | модель |
| | фокус исследования | модель на старте |
| Собрано | 8 элементов задачи: ✓ / ≈ / ✗ и его слова; пустое подсвечено | модель |
| Флажки | до 3, с видом: абстрактный критерий, склеенные задачи, подсказал интервьюер, намерение вместо траты, ушли от фокуса, мало времени, ловушка гайда | модель |
| Канон | ссылка на раздел канона | модель |
| Справка | стоп-лист, ловушки гайда, порядок «что резать» (свёрнуто, в широком окне) | `guide.json` |
| Подвал | последняя услышанная реплика; размер контекста сессии | транскрипт, CLI |

Адаптивность — задача дизайна (фаза 4). Архитектура обеспечивает одно: страница получает всё это одним `/state`, и раскладка по ширине — чистый CSS (одна страница, без двух интерфейсов).

**Окно.** Сейчас `NSPanel` всегда `.floating`, со `.fullScreenAuxiliary`. Предлагаю переключатель «поверх окон» в шапке панели, по умолчанию включён, состояние запоминается. Автоматически по ширине не переключать: это неожиданно, а большое окно рядом с Meet на втором мониторе тоже может быть нужно поверх. Страница сообщает окну о переключении через `window.webkit.messageHandlers`. Отдельно проверить в фазе 5, умеет ли `NSPanel` с `.nonactivatingPanel` уходить в полноэкранный режим. Если нет — «на весь экран» будет обычным развёртыванием окна.

## 8. Как проверять, что поведение не сломалось

1. **Детерминированно, на каждой фазе:** `uv run pytest` и `uv run ruff check`.
2. **Локальная регрессия парсера:** `bench/reparse-journals.py` по всем `recordings/live/*panel.jsonl` (раздел 5). Для v1 — ноль расхождений.
3. **Прогон по записи Андрея, до и после.** Одна и та же команда на восстановленной версии (фаза 0) и после переноса:
   ```bash
   scripts/copilot.py --no-defaults --context recordings/step2/context.md --mixed --replay-sys recordings/work/andrey-16k.wav --replay-seconds 1200 --speed 4 --no-window --port 8777
   ```
   Ответы модели недетерминированы, поэтому дословно журналы не сравниваются. `bench/compare-runs.py A/panel.jsonl B/panel.jsonl` сравнивает:
   - число обновлений и ошибок разбора (после — 0);
   - время ответа (медиана, максимум) и рост контекста;
   - сколько обновлений без вопроса, без блока, без задач;
   - как часто меняется вопрос (защита от мелькания) и сколько раз подряд он повторялся (защита от залипания).
   Смысл вопросов читаю глазами по двум журналам рядом и пишу в отчёте фазы.
4. **Прогон с гайдом** (с фазы 2): синтетический гайд по структуре шаблона + та же запись. Проверяем, что `БЛОК` и `ВОПРОС` ссылаются только на id из `guide.json`.
5. В CLAUDE.md, в разделе «Как запускать», появятся команды пунктов 1–3.
